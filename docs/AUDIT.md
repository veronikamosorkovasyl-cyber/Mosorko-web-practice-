## 2. Оптимізації / рекомендований список перевірки
- [ ] Poster images у WebP/AVIF, `width`/`height`, lazy loading нижче fold.
- [ ] Для hero-постера/контенту LCP не застосовувати lazy loading, якщо це LCP image.
- [ ] React route code splitting через `React.lazy` + `Suspense`.
- [ ] Debounce пошуку (300 ms) і не запускати зайві запити.
- [ ] Мінімізувати JS/CSS, прибрати непотрібні залежності.
- [ ] Не блокувати масштабування; responsive viewport.
- [ ] Стабільні розміри карток/постерів, щоб зменшити CLS.
- [ ] Loading, empty, error states для API.
- [ ] Перевірити кешування статичних ресурсів і compression на хостингу.
## 3. SEO
- [ ] Унікальний `title` для основних сторінок.
- [ ] Meta description, canonical за потреби.
- [ ] `robots.txt` з дозволом індексації публічних сторінок і блокуванням технічних маршрутів за необхідності.
- [ ] `sitemap.xml` для публічних сторінок/фільмів, не додавати URL з персональними даними.
- [ ] Open Graph: `og:title`, `og:description`, `og:image`, `og:url`.
- [ ] JSON-LD: `Movie` для сторінок фільмів, `Organization`/`WebSite` для сайту; structured data має відповідати видимому контенту.
- [ ] Семантична структура, один головний `h1`, описові link names.
## 4. Accessibility / axe
- [ ] Усі функції доступні з клавіатури: Tab, Shift+Tab, Enter, Space; місця мають керування клавіатурою.
- [ ] Видимий `:focus-visible`, focus order логічний.
- [ ] Skip link до main content.
- [ ] Accessible name для кожного seat: ряд, місце, статус.
- [ ] Статуси місць не позначаються лише кольором; використовувати текст/піктограму/патерн.
- [ ] Контраст ≥4.5:1 для звичайного тексту.
- [ ] Масштабування 200% без втрати функціональності.
- [ ] Форми мають label, текст помилок, `aria-describedby`; помилки доступні screen reader.
- [ ] Не використовувати `user-scalable=no`.
- [ ] axe DevTools: ціль 0 critical/serious; зберегти результати перевірки.

## 6. Vitest / React Testing Library
Перелік тестів, які мають бути присутні/перевірені; це не підтверджений список фактично запущених suite:
- `MovieCard`: назва, постер, жанр, duration, rating, CTA.
- `Search`: пошук за назвою та debounce.
- `Filters`: жанр/дата/кінотеатр, reset filters.
- `Seat`: стани free/occupied/selected/VIP та доступна назва.
- `SeatMap`: вибір, скасування, limit 8, occupied seat недоступне.
- `BookingSummary`: кількість і ціна; normal 220 грн, VIP 550 грн.
- `BookingForm`: required fields, email/phone, consent, submit state.
- `Booking`: успішна відповідь, 400 validation, 409 conflict.
- `ThemeToggle`: зміна теми й збереження налаштування.
- `ContactForm`: валідний submit та помилки API.
- `Loading/Error/Empty`: відображення відповідних станів.

## 8. Рекомендований процес аудиту
1. Запустити сайт у production та локально.
2. Lighthouse mobile/desktop — зберегти звіти, дату, URL і версію браузера.
3. Провести axe DevTools на головній, каталозі, схемі місць і формі.
4. Виконати 15 тест-кейсів; для кожного записати Pass/Fail, браузер, доказ/скриншот.
5. Провести 3–5 коридорних тестів із короткими завданнями; не підказувати користувачу.
6. Зареєструвати дефекти в GitHub Issues, прив'язати їх до тест-кейсів.
7. Після виправлень повторити тестування та заповнити колонку «Після».
